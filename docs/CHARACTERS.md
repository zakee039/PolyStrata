# PolyStrata 角色与世界书（第一版）

## 功能范围

角色卡、全局用户 Persona、简易关键词世界书、Markdown 文件/目录检索，均在 PolyStrata 的 Chat 页面使用。无需修改底层推理引擎，且不会修改第三方 OpenAI/Anthropic API 的请求内容。

### 使用方法

1. 打开 Chat → **Characters**，新建角色，填写身份、性格、场景、开场白及对话示例。
2. 在「世界书」新增手工条目，设置关键词或「常驻」。
3. 在「Markdown 资料」新增文件/目录来源，**输入运行 PolyStrata 的 Windows 电脑上的绝对路径**（可指向 OneDrive 同步目录）。目录可以递归扫描子目录的 `.md`、`.markdown` 文件。
4. 保存角色，输入测试问题后选择「测试检索」，可查看文件名、标题、命中片段及扫描时间。
5. 回到 Chat，在顶部选择角色；角色与会话绑定。不同会话可以选择不同角色，普通助手仍按原有方式聊天。

文件保留在原位置，PolyStrata **不移动、不复制、不改写** Markdown。检索缓存基于文件修改时间/大小自动刷新，适合本地和 OneDrive 已同步的文件。离线占位文件、失去访问权限或目录被移走时会提示问题并跳过检索，不会因此停止普通聊天。

## 运行方式

当前独立检索工作线程执行关键词与中文片段匹配、按 Markdown 标题分块、排序截断，并返回最多 4 段有来源标记的摘录；**它是独立的 CPU 检索子任务，还不是调用另一个 LLM 的智能子代理**。此设计不增加 GPU 模型常驻，不启动单独 LLM，也不会触碰 Gemma/Qwen 各自的 KV 快照。

需要时未来可以添加可选的「模型语义重排」阶段：只对粗检索得到的少量候选段落运行轻量模型判断相关性，且始终让主模型继续生成最终回复。模型重排不会默认开启。

第一版检索限制：每张角色卡最多 12 个资料源；每个目录最多扫描 200 个 Markdown 文件，每文件最大 256 KiB；每次最多返回 4 段、共计约 2300 字符；检索等待预算约 3 秒。超出限制的文件不会全部加载进上下文。单次检索失败直接继续普通聊天。

**安全说明：** 资料源是用户明确添加的服务器本机路径，管理接口要求 PolyStrata API Key 并受 Origin 检查保护。请勿添加含密钥、个人隐私或不希望发送给调用中模型的目录。检索到的 Markdown 按外部参考资料处理，不应视为给模型的行为指令。

## 角色卡导入导出

支持酒馆常见的角色卡 V1/V2/V3 **JSON** 的基础字段和世界书条目导入，并提供 V2 JSON 导出。为避免泄漏本地路径，导出的酒馆卡不包含本地 Markdown 路径绑定。角色卡 PNG 嵌入元数据、复杂的世界书触发规则、群聊、模型型子代理和语义嵌入尚未支持。

## 数据存储

角色、世界书、资料源路径、用户 Persona 与会话绑定写入服务器侧 `character_cards.sqlite3`，位于现有 SessionV1 会话目录下（PolyStrata 当前 Gemma/Qwen 注册配置均指向同一会话目录）。Markdown 原文不保存在角色数据库中，只有路径、索引缓存驻留内存。
